# ChatKit 共享对话核心：TL;DR

完整设计见 `2026-10-30-chatkit-shared-transcript-design.md`。

## 做什么

把 ChatKit 做成 iOS 和 Mac 共用的对话核心。列表机制（分页、锚点、行高缓存、跟随底部、离屏流冻结）放进 `ChatKitCore`，两端各用原生视图接上。Mac 借此补上长历史分页和附件。

## 你会看到的（按阶段）

1. **阶段 1，ChatKitCore**：界面不变。新增约 10 个带单元测试的纯逻辑类型，iOS 不动。
2. **阶段 2，Mac**：
   - 1 万条的会话也能秒开，只显示最新一页；滚到顶部自动加载更早的历史，阅读位置不跳。
   - 消息里的图片直接显示，点一下用 Quick Look 预览。
   - 输入框能加附件：回形针按钮、⌘V 粘贴、拖进窗口。发送后，进度显示在对话里那条待发消息上；发送失败时，文字和附件一起回到输入框。
3. **阶段 3，iOS**：看起来没有变化。内部换成同一套核心，原有的流式、滚动、发送 UI 检查全部重跑通过。

## 已定的决定

| 问题 | 决定 |
|---|---|
| 只修 Mac 还是两端共用 | 两端共用（B） |
| ChatKit 管到哪 | 只管列表机制（A）；消息样式由 Lody 注册，`lody-ios-bb` 同意 |
| 顺序 | Core → Mac → iOS（iOS 等 `lody-ios-bb` 改完） |
| Mac 发送后对话怎么动 | 照 iOS：发出的消息停在靠上的位置，下面留出空白，平滑滚动 |
| 行高缓存 key | 带上一行的类型，因为间距按前后两行决定 |

## 我自己做的决定（请过目）

- 跟随底部的动画数学（约 15 行）先复制一份进 Core，阶段 3 再删掉 LodyData 里的旧份。原因是 ChatKit 不能反向依赖 LodyData。
- 离屏流冻结也进 Core，这样 Mac 往上翻时，流式输出不会把阅读位置往下推。
- 上传进度照 iOS，显示在对话里的待发消息上，不显示在输入框。
- 新会话的上传如果失败，文字和附件恢复到这个新会话的回复框里。
- 阶段 3 开工前按当时的代码重新规划，因为 iOS 的行号和间距规则会因 `lody-ios-bb` 的改动而变。
- iOS 性能门槛：每项前后各跑 3 次取中位数，变差超过 10% 就算回归、挡住发布。
- `chat-kit` 是子模块，改动只做新增，不改现有 API；不推送，推送由你决定（先推子模块）。

## 时间估计

- 阶段 1：约 3–4 小时。
- 阶段 2：约 1–1.5 天（列表容器、分页、图片、附件、验证用例和 VM 测试）。
- 阶段 3：约半天到 1 天（主要是回归基线和对比）。
