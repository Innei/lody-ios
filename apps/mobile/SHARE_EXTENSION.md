# Native Share Extension

The system share sheet and the app's new-session page use one UIKit form and one
composer. `CreateSessionForm` owns selection/preferences, `CreateSessionController`
owns the list/composer, and `CreateSessionOptionsController` owns advertised model
options. `LodyCreateSessionView` is the Expo adapter, not a second form.

## Two hosts, one form

The app retains `definePage`/`present`, its durable outbox, session navigation and
native composer relay. Saving the initial outbox entry gates navigation; failure
publishes a failed fence before restoring the draft. If navigation fails after
save, “Open submitted conversation” opens that same session without resending.

The extension is a UIKit-only target generated by `withShareExtension.js` and
`share-extension.rb`. It compiles shared Swift sources by reference, with
`LODY_SHARE_EXTENSION` guarding app-only APIs. It does not link Expo, RN,
OneSignal, WebView, Loro or the data runtime. Prebuild + pods regenerate it; do
not edit generated Xcode files. Signing remains enabled. Distribution requires
both targets' App Group and shared Keychain entitlements in their profiles.

It ingests text, URLs, images and file providers, then uses the existing native
attachment upload API and Cloud's session-submission POST/GET pair. It never
launches the containing app, never copies desktop credentials, and never waits
for a machine or AI completion before acknowledging a durable submission.

## Persistence and recovery

`ShareStore` keeps an atomic, bounded catalog/options/preferences projection in
`group.app.innei.lody/Library/LodyShare`. The existing catalog owner publishes it;
there is no second subscription or SQLite/CRDT replica. Credentials stay in the
shared Keychain access group. No snapshot means “open Lody and sign in/refresh”.

Before uploading or sending, save a UUID receipt and private copies of attachment
files. Save the exact uploaded request body before POST. GET first; only a 404
allows POST of that same body and request ID. Interrupted uploads may be repeated;
an uncertain submission never gets a new request ID. App and extension share one
explicit “Previous submissions” recovery action; opening either host does not
automatically replay writes. Recovery disables interaction but does not consume
the current composer draft.

`submitted` means Cloud acknowledged metadata, initial history and dispatch.
`pending` means Cloud still retries. `unconfirmed` means retry budget expired or
authorization changed; it does not prove that no session exists. Completed local
receipts release attachments. Logout/account replacement clears local snapshots
and receipts; a cross-process lock and credential recheck fence late callbacks.
Workspace switching keeps receipts scoped to their original account/workspace.

Limits: text <=64 KiB UTF-8, eight images <=5 MiB after existing image processing,
eight files <=100 MiB, sixteen total. URLs are shared as text; no web-body scraping.
Unsupported provider/oversized inputs fail visibly instead of truncating silently.
GitHub repository discovery reuses the existing authenticated broker; project
branch selection remains explicit. Mentions in the app retain their existing
broker; the extension does not start a live mentions runtime.

## Rollout / verification

Deploy Cloud's additive submission API before releasing this client. Until then,
the extension preserves a failed/uncertain receipt for explicit retry. Existing
main-app sending does not depend on the new endpoint. Machine execution continues
through the existing dispatch watcher, including existing stale Agent-config
resolution behavior; a cached catalog is not a guarantee of machine readiness.

Run `pnpm check`, `pnpm test`, `pnpm bundle`, signed `pnpm verify:build`,
`pnpm verify:native --case create-session`, `--case create-session-ui`, and the
`model-memory` UI case. Native checks cover real composer state/draft preservation
and model memory; the UI case exercises the production host in English/light/dark.
`python3 apps/mobile/verification/ui/share-probe.py --app /path/to/Lody.app`
(also `--appearance dark --output .artifacts/share-probe/dark`) exercises the real
system share sheet with the app stopped and no credentials. AXe 1.8.0 is required.
Authenticated Cloud submission, attachment download, lost-response
recovery and offline-machine pickup must additionally be accepted after deployment.
